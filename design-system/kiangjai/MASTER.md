# Kiangjai 网站设计规则

版本：2026-10-23 ATS PICO 结构对照版。适用首页、安全中心、隐私、条款及共享组件。

## 优先级

1. 用户批准的原型业务内容及最新要求。
2. 用户明确指定的 ATS PICO 页面结构，实测见 [url-dna](../../design/url-dna.md)。
3. Kiangjai Logo、品牌色、App 原始界面，以及本项目实现规则。
4. Anthropic frontend-design、Impeccable colorize 与 UI UX Pro Max 的通用指导。

技能建议不得改写已审定内容，不以安装技能代替观察参考站。借鉴竞品的页面组织，不复制其素材、品牌、文案、费率或业务承诺。

## 布局与层级

| 项目 | 桌面 | 手机 ≤760px |
| --- | --- | --- |
| 共用内容最大宽度 | 1120px | 随视口 |
| 内容外边距 | 至少40px，超宽居中 | 24px |
| Hero 标题 | 52px / 1.4；中间宽度48/44px | 34px / 1.45；≤380px为32px |
| 主模块标题 | 44px / 1.5 | 30px / 1.5 |
| 正文 | 16px / 1.85 | 16px / 1.85 |
| 辅助/法律说明 | 14px / 12px | 14px / 12px |
| 分区上下留白 | 88px | 56px |
| 主要面板内边距 | 48px；≤1200px为40px | 24px；窄屏按组件20px |
| 主操作高度 | ≥56px | ≥56px |
| 画廊切换触控目标 | 桌面三图同时展示 | 44×44px，每点内部10px视觉标记 |

- 间距以8、16、24、32、40、48、56、88px组织；图形、细线和控件描边按用途定义。
- 页头、快捷入口、主面板、公司区、FAQ与页尾共用1120px内容轴。通栏 Hero 和品牌底色可铺满视口；不要用100vw计算页尾边距，避免滚动条偏差。
- 主模块标题居中；优势、安全、FAQ和面板内说明左对齐。桌面 Hero 信息组与公司介绍居中，手机改左对齐。步骤桌面居中横排，手机左对齐纵排。各类组件分别遵守固定规则，不做随意混排。
- Hero 使用 `market-life.jpg` 中完整人物与夜市场景，品牌主张→额度→优势→下载→原说明收在同一横幅内；手机重新安排人物与文字，不能遮挡脸部、操作或说明。
- Hero 后紧接品牌青三入口，桌面和手机均保持三个并列入口。
- 产品浅青区的三项优势与原安全提醒组成一个2×2白面板；手机为同一面板中的四行，图标在左、正文在右。
- 申请区将四步流程和三张完整 App 图放在一个白面板内；桌面四步横排、三图并列，手机步骤纵排、单图横向画廊。
- 公司/安全、FAQ/下载继续采用整组信息区，不拆成零散悬浮卡片。

## 颜色与形状

以 `assets/redesign.css` 的 tokens 为准：品牌 `#44E0F8`、深青 `#113F4A`、正文 `#202224`、辅助文字 `#59646A`、白色 `#FFFFFF`、浅灰 `#F4F7F7`、浅青 `#E8FAFD`、分隔线 `#D8E5E8`。

- 品牌青用于快捷导航、下载区、步骤和图标填充；浅青承载产品、申请与FAQ分区，白面板形成内容组。
- 标题、操作、链接和图标轮廓用深青；一般正文用中性黑灰，说明用辅助灰。深青胶囊按钮使用白字；禁止品牌青上白色小字。
- 主要白面板圆角24px，手机20px；截图保持统一圆角。只在可点击原图等必要组件使用克制阴影。
- Hero 的浅白渐变仅为生活场景上的文字可读性服务，不制作波浪拼贴、装饰光球或漂浮箭头。
- 对比度及字体来源见 [brand-colors](../../design/brand-colors.md)。

## 字体、图标与图片

- 所有可编辑文字统一自托管 Noto Sans Thai；SIL OFL文件随站保留。保持自然泰文断行，不使用 break-all，不裁掉变音符号。
- 优势图标为同一 Phosphor Duotone 家族：手机申请、银行到账、二维码还款、警示盾牌。四种语义轮廓不同，深青轮廓与品牌青填充统一；系统控件用 Lucide，方向符号仅用于真实操作。
- `market-life.jpg` 是完整夜市场景，允许响应式构图和可读性遮罩；不得替换为透明 `merchant-cutout.png`。场景不是客户证言或真实借款案例。
- 首页、选期、扫码还款三张 App PNG 原样保留，不改数字、文字或账户状态；不据此推导新条款。
- 三张界面位于申请面板，均按自然比例显示，禁止固定高度裁掉纵向内容。手机画廊每次展示一张，可横滑及点击三枚切换点；点击图片打开完整原图。截图内按钮不是网页交互控件。

## 交互与验收

- 可点击控件具备 hover、focus-visible、active 反馈；触控目标≥44px，主CTA≥56px。
- 使用真实 button、anchor、dialog；菜单、FAQ和画廊有状态；弹窗可Escape关闭并恢复焦点。
- 支持 prefers-reduced-motion，不增加自动播放与干扰阅读的入场动画。
- 普通正文对比度目标≥4.5:1，控件及功能图形≥3:1；信息不只依靠颜色。
- 检查1440、390、360及中间宽度：无横向页面溢出、泰文重叠，人物与文字互不遮挡，三张界面完整，画廊可操作。
- 原型181条泰语与四页原业务入口不变；不添加虚构牌照、人数、审批时长、评价或真实外部链接。
- 交付前实际浏览、保存截图、核查内容与动作，再更新同一公开预览。
